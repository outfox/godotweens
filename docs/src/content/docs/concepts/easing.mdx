Easing decides how motion speeds up and slows down; the duration stays the same.
The default, `EaseType.Linear`, moves at constant speed, which rarely suits
characters or UI. Pick an ease for every definition.

## Choose an ease

| Motion | Try | Why |
| --- | --- | --- |
| Arriving, settling into place | `CubicOut`, `QuartOut` | Starts fast, lands gently |
| Leaving the screen | `CubicIn`, `QuadIn` | Gathers speed on the way out |
| Moving between two resting spots | `SineInOut`, `CubicInOut` | Eases out of rest and into rest |
| A playful pop or emphasis | `BackOut`, `ElasticOut` | Overshoots, then settles |
| Dropping onto a surface | `BounceOut` | Lands with bounces |
| Constant motion, such as spinners or progress | `Linear` | No acceleration |

`Out` eases decelerate, `In` eases accelerate, and `InOut` does both. Every family
below has all three variants, such as `EaseType.CubicOut`.

## Compare the curves

<EasingPlayground />

| Family | Character |
| --- | --- |
| `Sine` | Gentle acceleration and deceleration |
| `Quad`, `Cubic`, `Quart`, `Quint` | Increasingly pronounced polynomial curves |
| `Expo` | Strong exponential acceleration and deceleration |
| `Circ` | Circular curve |
| `Back` | Overshoots an endpoint |
| `Elastic` | Oscillates around an endpoint |
| `Bounce` | Repeated bounces |

Back and elastic weights are not clamped. Overshoot suits motion, but native
property limits still apply to constrained values such as alpha or ranges.

## Custom functions and curves

Supply a function from normalized progress to weight:

```csharp
var eased = sprite.TweenPosition(new Vector2(300, 120), 0.5,
    options => options.EaseFunction = t => t * t);
```

`EaseFunction` overrides `Ease`. A Godot `Curve` can override `Ease` instead: its
samples use normalized time from 0 to 1, and each playback gets its own
duplicate. Set only one of `EaseFunction` and `Curve`; setting both is rejected.
An exception inside an easing function faults the tween.
